# Exact document snapshots for transaction recovery

## Status

Accepted for Phase 3.

## Context

An editor command may touch several JSON documents, and a command can fail after
performing only part of its mutation. Invoking command-level inverse operations
alone is therefore not sufficient to guarantee exact restoration, especially
when unknown fields, duplicate properties, original formatting, and plugin data
must remain intact.

## Decision

Before preview, commit, undo, or redo, capture the generated bytes of every
mutable JSON document named by the operation's mutation targets. If execution
fails or is cancelled, restore those bytes through the lossless JSON parser.
Command-level `UndoAsync` remains the normal history mechanism, while exact
snapshots form the atomic safety boundary around the operation.

Snapshots are held in memory only for the duration of the operation. Map paint
commands retain sparse tile deltas in history rather than complete map arrays.

## Consequences

- Partial command execution cannot leave targeted documents half-mutated.
- Preview can execute real commands and then restore the exact prior state.
- Undo and redo failures restore the state that existed before the attempted
  history operation.
- Commands must truthfully enumerate every document they can mutate.
- Non-JSON document transactions require a future document-specific snapshot
  provider before they may participate in this boundary.
